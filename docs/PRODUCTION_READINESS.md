# 本番化・改善ロードマップ

レビューで指摘されたリスクを、現行MVPを壊さずに改善するための運用メモです。

## 現時点で反映済み

- ロゴアップロードを PNG / JPEG / WebP のみに制限
- ロゴ画像の容量上限と総ピクセル数上限を設定
- 素材ギャラリーの画像を遅延ロード化
- 素材数が増えても初期表示を絞れる「さらに表示」を追加
- localStorage の保存件数を制限し、保存容量エラーを画面に返す
- `npm test` でHTML参照、素材画像、主要セキュリティ設定を確認

## 技術スタック方針

短期は、現在のVanilla JS版を「検証用MVP」として安定化します。理由は、現行版にロゴ配置、3D確認、仕様書保存まで入っており、Reactへ急に置換すると機能欠落のリスクが高いためです。

中期でReact/TypeScriptへ移行する場合は、以下の順で進めます。

1. 現行の `scripts/api-client.js` と `scripts/mock-db.js` のデータ契約を固定する
2. 表示部品を「条件入力」「提案カード」「素材ギャラリー」「編集プレビュー」「サイズ確認」「仕様書」に分ける
3. まずVite + React + TypeScriptへ画面単位で移植する
4. Fabric.js と 3D表示は最後に統合し、現行MVPと見比べて機能差分を潰す

## テスト・ステージング環境

ローカル:

- `index.html` を直接開く、または任意の静的サーバーで確認
- `npm test` で参照ファイルと素材画像の存在を確認
- 外部APIなしの `mock` モードでUIと保存フローを検証

ステージング:

- 本番とは別のSupabaseプロジェクトを用意
- 本番とは別の画像ストレージバケットを用意
- テスト用問い合わせメールだけに通知
- テスト用の素材・ロゴ・顧客情報のみ投入

本番:

- APIキーはブラウザへ直接出さず、サーバー側APIで保持
- 問い合わせ、顧客情報、ロゴ画像は保存期限と削除手順を決める
- 画像ストレージは公開素材と非公開ロゴを別バケットに分ける

## セキュリティ方針

- `.env` やAPIキーはGitへ入れない
- OpenAI APIキー、Supabase service role key、Storage secret keyはサーバー側だけで使う
- ロゴアップロードは拡張子ではなくMIMEタイプ、容量、画像サイズで検証する
- SVGアップロードはスクリプト混入リスクがあるため、MVPでは許可しない
- 本番APIでは問い合わせ本文、会社名、メールアドレスの長さ制限と監査ログを入れる
- 管理画面を作る場合は認証必須にし、素材登録・問い合わせ閲覧を権限で分ける

## パフォーマンス方針

- 素材画像はサムネイル用と原寸用を分ける
- 一覧表示はWebP/AVIFサムネイルを使う
- 画像はCDN配信し、Cache-Controlを長めに設定する
- ギャラリーは初期表示件数を制限し、ユーザー操作で追加読み込みする
- 3D表示は低スペック端末向けに2D表示へ切り替えられる導線を残す

## データ保持方針

現行MVPはブラウザ内のlocalStorage保存です。これは試作用であり、端末を変えると共有できません。

本番では以下を永続化します。

- design_sessions: 条件入力
- generated_designs: 提案案
- estimates: 見積り
- inquiries: 問い合わせ
- uploaded_assets: 顧客ロゴと利用範囲

問い合わせデータは、商談終了後の削除期限を事前に決めます。
